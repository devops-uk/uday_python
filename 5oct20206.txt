AWS supports a TOKEN Lambda authorizer on REST APIs with an identity source such as method.request.header.Authorization; 
setting the authorizer result TTL to 0 disables caching, matching what we configured manually. AWS Documentation
For GuardDuty, I used AWS's documented malware-protection service-role permissions: managed EventBridge rule access, 
S3 notification configuration, validation object, bucket ownership check, object read/version read, and tagging. 
Because we're using SSE-S3 (AES256) rather than SSE-KMS, the KMS permissions from AWS's generic example are intentionally omitted.
